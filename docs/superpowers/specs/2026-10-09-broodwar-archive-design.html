Date2026-10-09
StatusDRAFT · REVIEW
Repobroodwar-archive

Find, restore, and preserve televised Korean Brood War broadcasts, and make them accessible and as complete as possible. The restored footage is the point. The catalog and site exist to serve it and to show what is still missing.

§2Scope

In

  • Televised and official matches: OSL, MSL, Proleague, later ASL/KSL
  • Restoring the best available copy of each match
  • Player identity, including ladder and smurf IDs, stored as claims
  • .rep replays attached to a game when found

Out for now

  • Ladder, smurf, and small-stakes games as catalog entries
  • Re-rendering matches from replays
  • Editorial history and current-scene content (planned, not built)
  • Hosting and streaming video ourselves

§3Principles

  1. Master and access copy are never confused. Each restored match has an untouched preservation master and a separately labeled copy for watching. The master lets a better future pipeline re-run instead of re-hunting the footage.
  2. The master invents nothing. The access copy may be enhanced conservatively, and every change is recorded.
  3. Lots of copies keep stuff safe. Redundancy makes the archive accessible. A takedown removes one mirror and leaves the archive intact.
  4. The catalog is the spine. Plain files in a public git repo, enough to rebuild everything else.
  5. Knowledge is a claim with a source. Claims can be disputed and upgraded.
  6. Gaps are computed. The "what's missing" view updates as soon as a source is added.
  7. Design for contributions. Completeness depends on people in the scene who hold footage and knowledge.

§5Data model

Core chain: Event → Series → Game, plus Player, Map (the version is part of a map's identity), and Team. Three entities carry most of the design:

EntityWhy it exists
SourceSegmentOne upload is often a whole broadcast with pre-show, ads, and several series. A segment maps source + time range → game, so the catalog can say set 4 is at 47:00–71:00 of an upload and set 5 is missing from it.
IdentityClaimplayer ← alias with valid_from / valid_to, kind (broadcast name, ladder ID, smurf), confidence (confirmed, community-attributed, rumored), and who asserts it. 임요환 = Lim Yo-hwan = BoxeR, with each name tied to a date range.
RestorationSegment, recipe, pipeline version, output files, and ledger entry.

Every source gets a quality grade. A game whose best source falls below the threshold shows up as a gap.

Anear source
Bclean re-encode
Cdegraded, complete
Dpartial or damaged
Xknown lost

§7Restoration pipeline

  1. Probeffprobe, MediaInfo, and sample frames: field order, interlaced, progressive, or telecined, true vs. flagged aspect ratio, audio offset, burned-in damage.
  2. RecipeThe tool proposes a YAML recipe and a person approves it. Old uploads vary too much to automate the decision.
  3. MasterKeep the original byte for byte. Make a lossless FFV1/MKV intermediate trimmed to the segment, fixing only field-order and aspect flags.
  4. Access copyDeinterlace with bwdif (QTGMC optional for important matches), correct the aspect ratio, light denoise, modest upscale, fix audio sync, encode HEVC with VideoToolbox.
  5. EvidenceBefore/after stills at the same timestamps, plus notes on what was wrong and what was changed.
  6. Ledgersha256 of every input and output, recipe hash, tool versions, timestamp.
  7. PublishMaster to tier 1, access copy to archive.org, restoration record into the catalog.

§8Site

  • Match page: metadata, best existing copy, restored copy, before/after slider, technical notes, provenance.
  • Event page: every game in the event with its best source grade, which doubles as that event's gap map.
  • Later: player identity timelines, map pages, an era explorer, current-scene pages, and a contribution form.

§9Slice one

5–10 matches from one event. Pick matches that are historically notable, have a visibly bad best copy today, and can be found online. You choose the event when we write the plan.

Done-gateI open the public site, pick a match from the slice, see the best existing copy next to my restored copy with notes on what was fixed, and can stream or download the restored file.
  1. CatalogSchema, validator, and the slice's event entered by hand. Check: valid files pass and a deliberately broken file fails.
  2. ProspectFind and probe copies for those games. Check: each game has source and segment records, and gaps are visible.
  3. Restore oneMaster, access copy, and stills for one game. Check: the stills show a visible fix and the checksums are in the ledger.
  4. Publish oneUpload to tier 1 and archive.org. Check: the archive.org item streams.
  5. SiteBuild match and event pages. Check: run the done-gate on the deployed site.
  6. WidenRepeat restore and publish for the rest of the slice.

§10Stack

  • Python CLI for catalog, prospector, restorer, and ledger
  • ffmpeg 8 and yt-dlp (installed), MediaInfo (to install), VapourSynth with QTGMC (optional, later)
  • Catalog as YAML in git, validated against a JSON Schema
  • Static Astro site with free hosting
  • internetarchive Python library for uploads

§11Risks

RiskMitigation
Rights-holder takedownNo self-hosted video. Mirrors on archive.org and torrents. The catalog stands apart from every mirror.
Inputs are re-encodes, not mastersGrade sources honestly. Use scene contacts to find copies closer to the original broadcast.
Identity errorsRecord each alias as a claim with confidence and a source. Never assert one without them.
Storage cost grows with the archiveTiered storage with cold masters. Measure per-match size during slice one before scaling.
No CUDA on Apple Siliconbwdif by default, QTGMC only for important matches.
Scope creep into editorialOut of scope until slice one passes its done-gate.

§12Verify before relying on

  • Liquipedia's content license and API terms, since it is the planned catalog seed
  • The internetarchive upload API, and whether archive.org's collection policy fits this material
  • Estimates: total broadcast matches (roughly 10,000 or more) and per-hour master and access file sizes, to be measured in slice one
